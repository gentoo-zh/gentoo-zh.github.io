[gentoo-zh](https://github.com/gentoo-zh/overlay) is an overlay maintained by the Gentoo Chinese community. It grew out of gentoo-tw and gentoo-china in 2003 and provides packages commonly used by Chinese-speaking users.

{{< callout type="info" >}}
Git, Distfiles and binary packages can use different mirrors. The configurations on this page update when you select a mirror.
{{< /callout >}}

- **Chinese input methods and fonts**: fcitx, pinyin dictionaries, Chinese fonts
- **Applications popular in China**: WeChat, QQ, DingTalk, WPS Office, Feishu, NetEase Cloud Music
- **Networking and proxy tools**
- **Patched desktop / performance kernels**: cachyos-sources, xanmod, liquorix
- **Development and everyday tools**

## Adding the overlay

These mirrors provide Git synchronization for the gentoo-zh ebuild repository. They do not contain package source files.

{{< gz-mirror name="git" >}}

Install `eselect-repository`, then add and synchronize the overlay from the selected mirror:

{{< gz-cmd path="shell" sudo="true" >}}
emerge --ask app-eselect/eselect-repository
eselect repository add gentoo-zh git @@SRC@@
emaint sync -r gentoo-zh
{{< /gz-cmd >}}

{{% details closed="true" title="Manual configuration or changing mirrors" %}}

For a new configuration, create `/etc/portage/repos.conf/gentoo-zh.conf`. To change Git mirrors, edit the file under `/etc/portage/repos.conf/` that contains the `[gentoo-zh]` section. Configurations generated by `eselect-repository` are stored in `/etc/portage/repos.conf/eselect-repo.conf`.

Complete configuration example:

{{< gz-cmd path="/etc/portage/repos.conf/gentoo-zh.conf" >}}
[gentoo-zh]
location = /var/db/repos/gentoo-zh
sync-type = git
sync-uri = @@SRC@@
auto-sync = yes
{{< /gz-cmd >}}

After changing mirrors, remove the existing local repository and synchronize it again:

{{< gz-cmd path="shell" sudo="true" >}}
rm -rf /var/db/repos/gentoo-zh
emaint sync -r gentoo-zh
{{< /gz-cmd >}}

{{% /details %}}

## Accept the testing keyword

gentoo-zh packages have `~ARCH` (testing) keywords only. Systems that use `~amd64` globally can skip this step; systems using stable keywords must accept `~amd64` first.

See the [Gentoo Wiki](https://wiki.gentoo.org/wiki//etc/portage/package.accept_keywords#.7EARCH_system-wide) for details about `~ARCH`.

The `::gentoo-zh` qualifier applies only to this overlay. You can accept `~amd64` for the entire overlay without affecting packages from the Gentoo repository:

{{< gz-cmd path="/etc/portage/package.accept_keywords/gentoo-zh" >}}
*/*::gentoo-zh ~amd64
{{< /gz-cmd >}}

You can also accept testing keywords package by package:

{{< gz-cmd path="/etc/portage/package.accept_keywords/gentoo-zh" >}}
net-im/tencent-qq ~amd64
{{< /gz-cmd >}}

## Install a package

{{< gz-cmd path="shell" sudo="true" >}}
emerge --ask net-im/tencent-qq
{{< /gz-cmd >}}

To list what the overlay provides: `eix -RO gentoo-zh`.

## Distfiles and binary packages

The Distfiles and binary package services are independent and can be configured separately.

### Distfiles mirror

These mirrors provide only the Distfiles used by the gentoo-zh overlay, so append them to the existing configuration. See the [mirror list](/en/mirrorlist/) for `::gentoo` Distfiles.

{{< gz-mirror name="dist" set="dist" >}}

{{< gz-mode name="dist" >}}

{{% gz-pane group="dist" name="manual" %}}
{{< gz-cmd path="/etc/portage/make.conf" slot="dist" >}}
GENTOO_MIRRORS="${GENTOO_MIRRORS} @@LIST@@"
{{< /gz-cmd >}}
{{% /gz-pane %}}

{{% gz-pane group="dist" name="quick" %}}
{{< gz-cmd path="shell" sudo="true" slot="dist" >}}
tee -a /etc/portage/make.conf > /dev/null <<'EOF'
GENTOO_MIRRORS="${GENTOO_MIRRORS} @@LIST@@"
EOF
{{< /gz-cmd >}}
{{% /gz-pane %}}

`GENTOO_MIRRORS` is tried in order. The selected mirror comes first and the origin last. Do not append `distfiles/` to these addresses because Portage adds it automatically.

### Binary packages (binhost)

[gentoo-zh binhost](https://github.com/gentoo-zh/binhost) provides signed amd64 binary packages in stable and unstable channels. It also includes the subset of `::gentoo` runtime dependencies required by gentoo-zh packages; it does not replace the [official Gentoo binhost](https://wiki.gentoo.org/wiki/Gentoo_Binary_Host_Quickstart).

{{< gz-channel name="bin" >}}

{{% gz-channel-pane group="bin" name="stable" %}}
stable uses stable packages from the Gentoo repository and accepts `~amd64` only for `::gentoo-zh`. Select it when the Gentoo repository uses stable keywords.
{{% /gz-channel-pane %}}

{{% gz-channel-pane group="bin" name="unstable" %}}
unstable uses `~amd64` globally. Select it only on systems configured with `ACCEPT_KEYWORDS="~amd64"`.
{{% /gz-channel-pane %}}

See the [gentoo-zh package list](https://distfiles.gentoozh.org/packages) for current package counts and status, and the [gentoo-zh binhost FAQ](https://distfiles.gentoozh.org/faq#binpkg-channel) for a channel comparison.

{{< gz-mirror name="bin" set="dist" >}}

{{< gz-mode name="bin" >}}

Import the signing key:

{{< gz-cmd path="shell" sudo="true" >}}
emerge sec-keys/openpgp-keys-gentoozh
getuto
gpg --homedir /etc/portage/gnupg --import /usr/share/openpgp-keys/gentoozh.asc
gpg --homedir /etc/portage/gnupg --batch --yes --pinentry-mode loopback \
    --passphrase-file /etc/portage/gnupg/pass --lsign-key 6A0726AF1476A2F382C6AC6638A0234EC16AD42E
gpg --homedir /etc/portage/gnupg --check-trustdb
{{< /gz-cmd >}}

`getuto` creates `/etc/portage/gnupg` and the Portage Local Trust Key, so run it before importing the key. Verification runs as the `portage` user, which requires the trust database to be generated in advance.

{{% gz-pane group="bin" name="manual" %}}
Add the binary package repository:

{{< gz-cmd path="/etc/portage/binrepos.conf/gentoo-zh.conf" slot="bin" channel="bin" suffix="/binpkgs/x86-64" >}}
[gentoo-zh]
sync-uri = @@SRC@@
priority = 10
verify-signature = true
location = /var/cache/binhost/gentoo-zh
{{< /gz-cmd >}}

Automatically download and install a suitable binary package when one is available:

{{< gz-cmd path="/etc/portage/make.conf" >}}
FEATURES="${FEATURES} getbinpkg"
{{< /gz-cmd >}}
{{% /gz-pane %}}

{{% gz-pane group="bin" name="quick" %}}
{{< gz-cmd path="shell" sudo="true" slot="bin" channel="bin" suffix="/binpkgs/x86-64" >}}
mkdir -p /etc/portage/binrepos.conf
tee /etc/portage/binrepos.conf/gentoo-zh.conf > /dev/null <<'EOF'
[gentoo-zh]
sync-uri = @@SRC@@
priority = 10
verify-signature = true
location = /var/cache/binhost/gentoo-zh
EOF

tee -a /etc/portage/make.conf > /dev/null <<'EOF'
FEATURES="${FEATURES} getbinpkg"
EOF
{{< /gz-cmd >}}
{{% /gz-pane %}}

When no suitable binary package is available, Portage builds from source as usual.

To use binary packages for one command:

{{< gz-cmd path="shell" sudo="true" >}}
emerge --ask --getbinpkg <package>
{{< /gz-cmd >}}

{{< callout type="warning" >}}
`verify-signature = true` requires signature verification for this repository only. Enabling the global `FEATURES="binpkg-request-signature"` also requires signing packages built locally through `FEATURES="buildpkg"`.
{{< /callout >}}

{{< callout type="info" >}}
See the [gentoo-zh binhost FAQ](https://distfiles.gentoozh.org/faq) for channel details and key download instructions. See the [Binary package guide](https://wiki.gentoo.org/wiki/Binary_package_guide) for advanced configuration.
{{< /callout >}}

## Worth knowing

{{< callout type="info" >}}
As of October 2025 the official project no longer provides cache mirrors for third-party repositories, so gentoo-zh syncs directly from GitHub upstream. If you added it before then, update your sync source — see [this note](/posts/2025-10-07-thirdparty-repo-mirror-removal/).
{{< /callout >}}

- The repository is [gentoo-zh/overlay](https://github.com/gentoo-zh/overlay). The old `microcai/gentoo-zh` redirects (301) to it; if you wrote the remote by hand, update it. See the [migration record](/posts/2026-07-02-gentoo-zh-repo-migration/)
- The CERNET united mirror stores nothing itself: it forwards the request to a nearby member site, so git reports one redirect, which is expected
- The mirrors are not always equally fresh; if one serves an older version of a package, switch to another and sync again
- For packagers: if a package's source should not be mirrored, for copyright or similar reasons, add `RESTRICT="mirror"` to its ebuild and the sync tool skips it
